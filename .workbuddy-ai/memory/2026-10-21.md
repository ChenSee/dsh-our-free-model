## 修：渠道模型「测一次」报 Unknown model

**现象**：设置页对 `codearts/deepseek-v4.1-flash` 点测一次 → 404 `Unknown model "codearts/deepseek-v4.1-flash"`；`big-pickle` 正常。

**根因**：`packages/standalone/service.mjs` 里包装 runtime 时，`catalog` / `state()` /
`publicModelRows()` 都拼上了 `channels.publicModelRows()`（渠道行 id 形如 `provider/model`），
但 `testModel` 是 `...core` 展开来的核心实现 —— 它闭包里只查 `core.catalog`，
那里没有渠道行，于是页面列得出、却测不了。`complete` 有分派，`testModel` 漏了。

**修复**：
- `packages/standalone/channels/runtime.mjs`：抽出 `handles`，新增 `testModel(model, {signal})`
  —— 走同一条 worker `complete` 通道发一次真实最小生成，返回形状对齐 `core.testModel`
  （ttftMs/latencyMs/outputTokens/reasoningTokens/tokensPerSecond/sample/text），
  失败按 404（worker statusCode）/文本为空/意外 tool call 分类；统计记 `origin: 'bench'`。
- `packages/standalone/service.mjs`：包装层加
  `testModel: (id, effort, options) => channels.handles(id) ? channels.testModel(id, options) : core.testModel(id, effort, options)`。

**验证**（复制数据目录到临时路径 + 18955 端口起独立实例，测完已清理）：
- `codearts/deepseek-v4.1-flash` → 200，`sample:"OK"`，ttft 65s（渠道本身慢）
- `nope/nothing` → 404 Unknown model（未误吞）
- `big-pickle` → 502 Rate limit（免费车道限流，说明核心路径照旧打到上游）

**归因（用户追问「谁改的」）**：缺口来自 2026-10-08 的 `14f1d03 feat(独立服务)：统一渠道推理与管理接口`
（zixin947）—— 那次把 `channels.publicModelRows()` 拼进 catalog/state/publicModelRows 并给
`complete` 加了分派，唯独没覆盖 `testModel`。`git log -S "channels.testModel" --all` 为空，
说明历史上从未有过这条分派；之后 service.mjs 只改过陈旧锁（c52004b / d2ff6a8 / 9d083f8 / 158ab1e）。
**不是最近改坏**：今天 16:37 `channel-credentials.json` / `channel-pack/state.json` 刷新（11 个渠道账号），
渠道行才成批出现在模型页，第一次点渠道模型的「测一次」就撞上。`/models/test` 端点本身更早
（`cd244d3`，同日，走 core 目录）。

## 全自动发版（auto-release.yml）

用户问「同步上游就发版」，新增 `.github/workflows/auto-release.yml`（commit 1bddbc1）：
- 触发：push main（GitHub Sync fork 即触发）+ schedule `*/30 * * * *` + workflow_dispatch(force)
- 检测：curl 上游根 package.json version，与 `packages/desktop-electron/package.json` 比较；
  `git ls-remote --tags origin refs/tags/v$ver` 已存在则 skip（幂等）
- 合并：fetch + merge upstream/main，冲突则 `::error::` 退出
- 门禁：`npm install --ignore-scripts` + `npm --prefix packages/standalone ci`
  （test:contributor 里 standalone-client-regression / standalone-page-lifecycle 需要 esbuild）
  + `npm run test:contributor` + `npm run manifest:check`
- 发布：只替换 version 行 → commit → 推 main（3 次重试，先 merge origin/main）
  → `git tag -a v$ver` → push tag → `gh workflow run build-windows.yml --ref v$ver`
- 关键点：GITHUB_TOKEN 推 tag 不会触发 workflow（防递归），workflow_dispatch 是官方例外，
  所以不需要 PAT。workflow 自身 push main 用 `actor != github-actions[bot]` 挡回环。
- 首次运行（push 1bddbc1）已验证：detect 成功、其余步骤 skipped（版本已对齐 + tag 已存在）

**2.5.8 结果**：Release v2.5.8 已发布，资产 `Our.Free.Model.Setup.2.5.8.exe`（135 MB）；
v2.5.7-fix 的 Release 也在（资产名 2.5.7）。build-windows 在 tag 上 2 分钟构建成功。
