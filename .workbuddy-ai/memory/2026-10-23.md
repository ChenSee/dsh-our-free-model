## 查：qoder/qfmodel「一直连不上」

**结论：不是连不上，是国际版 `qoder` 的 `qfmodel`(Qwen3.8-Flash) 一直在服务端排队
（`10605`），而排队最长要等 30 分钟 —— 用户看起来就是「卡住/连不上」。中国版正常。**

### 排除过程（三步，每步都有实测）

1. **先排网络**：`api2.qoder.sh` / `gateway.qoder.com.cn` / `qoder.com` /
   `api2-v2.qoder.sh` 直连与代理下 TCP+TLS 都在 100~600ms 内完成；零凭据 POST 稳定回
   `{"code":"101","message":"Signature invalid"}` ⇒ **链路完全通**，不是代理/防火墙。
2. **排凭据**：`~/.our-free-model/channel-credentials.json` 里 `QODER_ACCOUNT_F08D2836`
   与 `QODERCN_ACCOUNT_F785D165` 的 `uid` / `machine_id` / `refresh_token` 齐全，
   `expire_time` 分别是 2026-11-20 / 2026-11-17，**都没过期**；`state.json` 里
   `modelRateLimits`（qfmodel→10-20、dfmodel→10-21）也早已过期自动解除。
3. **用真实凭据跑加密链路**：国际版 `qfmodel` 三轮全部命中排队帧
   `{"isQueued":true,"modelKey":"qfmodel","queueType":"p3","serviceAvailable":false,
   "retryAfterSeconds":30,"waitTime":30}`；`qmodel` / `auto` / `dmodel` 回 **`code 112`**
   （带 `pricingUrl` = 无额度/付费墙）；中国版 `qfmodel` / `dfmodel` / `qmodel_38max`
   **全部正常出流**。

### 代码侧的口径

- 排队 `10605` 已有处理：`waitForQueue` 按服务端给的 `retryAfterSeconds` 等待，
  `QUEUE_MAX_ATTEMPTS=180`、`QUEUE_MAX_DELAY_MS=10_000`（单次封顶 10s，
  故服务端要 30s 时需连等 3 次）。
  所以现象是**长时间无输出**而非报错。
- ⚠️ **`code 112`（无额度/付费墙）代码里没有分支**，会走普通错误抛出，
  与排队是两种完全不同的处置，排查时要先分清。

### 副作用与教训

- 排查时把 `vendor/channel-pack/qoder-auth-wasm.wasm` 复制到包根跑探针，清理时
  `rm` 误删了**受版本控制**的 `src/qoder-auth-wasm.wasm`，已用

### 复用要点

- 签名 = Ed25519，`crypto.sign(null, stableStringify(signaturePayload(parseManifest(m))), key)`；
  **验签必须先 `parseManifest(m)`**再 `verifyManifestSignature`，直接传原始 manifest 会返回 false（踩过）。
- `release-sign.yml` 只在 `--check` 失败或 `force` 时才重签；`--check` 通过时整段 no-op，
  所以「manifest 已自洽」时它成功也不代表它签过。
