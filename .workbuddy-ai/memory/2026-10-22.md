**用户诉求**：新版本（上游 2.5.9）无法合并，要求排查并解决。

### 冲突根因
上游发 2.5.9（origin/main 前进到 482500f），本地 main 领先 17 个提交。
`git merge-tree` 预演发现冲突全部在 `packages/standalone/web/`（构建产物）：

本质：web/ 是 hash 命名的构建产物，两侧各自重建必然撞。真实源码（runtime.mjs /
desktop-test.mjs / package-lock）都能 auto-merge。

  然后 `node scripts/build-standalone-ui.mjs` 用合并后源码重建整目录（settings 又变成
  `settings-BoNS3jSm.js`，与上游 BbcpaUEV 不同属正常 hash 漂移），`git add web/`
- 合并提交 691bae9；清单不含 web/（覆盖 80 个插件文件），manifest:check 通过
- 推 chensee/main（bffb316..691bae9）→ 触发 auto-release

## 复盘：403 的真根因（推翻上面的初判）

**初判错了两次，最终靠证据定案：**
1. 先说「workflow_dispatch 触发才没权限」→ 用本机凭据重推 tag 走 push 事件，**仍 403**，否定。
2. 再说「fork 仓库内置 token 不能建 Release」→ 查历史 Release 的 author，
   v2.5.6/2.5.7/2.5.7-fix/2.5.8/2.5.8-fix **全是 `github-actions[bot]`**，
   证明历史上内置 token 一直能发，也否定。
3. **真根因**：仓库设置 `GET /repos/.../actions/permissions/workflow` 返回
   `default_workflow_permissions: "read"` —— Actions 内置 token 默认只读。
   即使 workflow 文件里写了 `permissions: contents: write`，run 日志的
   `GITHUB_TOKEN Permissions` 也只给到 `Contents: write` + `Metadata: read`，
   但创建 Release 的 POST /releases 仍被判 403。
   → 用 `PUT .../actions/permissions/workflow {"default_workflow_permissions":"write"}`
   （HTTP 204）放开后，重跑构建即恢复：安装包由 `github-actions[bot]` 成功上传。

**验证方法（重要）**：`gh release create` 失败后会 `|| gh release upload --clobber` 兜底，
日志里出现 `a release with the same tag name already exists` + 上传成功 = 权限已恢复
（上传同样需要 contents:write），不能只看 job 绿色就断言。

**v2.5.9 最终状态**：Release v2.5.9（author=ChenSee，因先用 PAT 建了壳），
资产 `Our.Free.Model.Setup.2.5.9.exe` 128.8 MB，uploader=`github-actions[bot]`。
tag v2.5.9 → d322f2e（annotated，指向 5d23a5d）。

**已落地的两处 CI 修复**：
- `2d28338` auto-release：`gh workflow run build-windows.yml -R "$GITHUB_REPOSITORY"`
  —— 否则 gh 从 git remote 命中 upstream(Ebony-Vinyl)，上游无此文件 → 404。
- `af3cd3d` build-windows：发布步骤 `GH_TOKEN: ${{ secrets.RELEASE_PAT || github.token }}`
  —— 留作兜底；若仓库默认权限再被改回 read，配一个 repo scope 的 RELEASE_PAT 即可免改设置。
- 仓库设置侧：`default_workflow_permissions` 已由 read 改为 write（这一步才是真正的修复）。

**教训**：`gh` 在 Actions 里解析仓库会命中 git remote（上游），跨仓库操作一律显式 `-R`。
